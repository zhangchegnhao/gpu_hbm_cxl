# KV Cache Capacity and Attention Sensitivity Sweep v1

This first KV-stage artifact is a controlled analytic sensitivity study for the
existing real Qwen3 pilot. It keeps the expert IDs and weights from the first
pilot layer-batch, tiles that routing template to the requested batch size, and
sets a uniform context length for each row. Latency and throughput cover all
48 serial layers and one Decode step, repeating the same routing template at
every layer. The policy may choose a different GPU/PIM placement as Context
changes; fixed routing does not mean fixed placement. It does not create a new Router
trace and it does not add KV READ requests to Ramulator.

The sweep is generated by `scripts/run_kv_capacity_sweep.py` with the matrix
specified in the project protocol. Its authoritative outputs are
`results/kv_capacity_sweep_v1/sweep.csv` and `sweep.json`; the four PNG/SVG figures
show KV size, peak-memory heatmap, Attention latency, and Attention latency
share. `baseline_summary.json` is the previously completed real-pilot
`ramulator-table-v0` result for the selected policy, while
`baseline_breakdown.json` extracts its Attention, Expert, KV, peak-memory, and
throughput fields. Expert time uses the critical path rather than summing
overlapping GPU/PIM event durations. The historical baseline covers eight
Decode steps; both baseline files are kept separate from the analytic sweep rows.

The model gives 98,304 bytes of full-model KV per token. At B=8/C=4k the sweep
estimates 3,221,225,472 bytes of KV and 64,286,167,040 bytes of peak memory.
At B=8/C=32k, peak memory is 86,834,745,344 bytes: feasible in the 96 GB
simulated capacity but above the 80 GB physical A800 capacity. B=16/C=32k and
B=32/C=16k exceed the 96 GB simulated capacity and are marked `infeasible`.
These states are capacity estimates; no paging, spill, eviction, or OOM
behavior has been implemented.

The Attention, total latency, and derived request-token throughput columns are analytic roofline estimates using
the existing hardware configuration. They are not A800 measurements and are
not Ramulator results. Infeasible rows retain unconstrained analytic latency
and throughput for sensitivity analysis; these are not executable performance
estimates. Five new long-context captures and their subsequent simulated
replays are recorded separately in `docs/kv_long_context_capture_v1.md` and
`docs/kv_long_context_cycle_v1_analysis.md`.
